Java · Depuración

¿Cómo funciona un depurador de Java?

Un depurador (debugger) te deja parar un programa en mitad de su ejecución y mirar dentro: qué línea toca, qué valen las variables y quién llamó a quién. Pruébalo tú mismo.

1. Simulador 2. Por dentro 3. Los botones

1. Simulador de depuración

Pulsa Debug. El programa corre hasta el punto rojo (breakpoint) y se para. Después avanza con los botones. Haz clic en el círculo junto a un número de línea para poner o quitar un breakpoint.

    2. Por dentro: el IDE habla con la JVM
    
      
    
        Tu programa corre en la JVM (Java Virtual Machine). El IDE (IntelliJ, Eclipse, VS Code…) es otro programa distinto.
        Hablan por un canal llamado JDWP (Java Debug Wire Protocol). El IDE pide cosas; la JVM responde.

      ¿Cómo se activa?
      
        
      Se arranca la JVM con un “agente” de depuración. Así el IDE se conecta al puerto 5005:
      
        
      java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 Main
      
        
      Cuando pulsas Debug en el IDE, él hace esto por ti.
      
      
      
    
      

    
    
      
      
      3. Los botones, uno a uno
      
      
      
        
      Breakpoint
      Una marca roja en una línea. Cuando el programa llega ahí, se para.
      
        
      ▶
      Resume
      “Sigue”. El programa corre hasta el siguiente breakpoint o hasta el final.
      
        
      ⤼
      Step Over
      Ejecuta la línea entera. Si llama a una función, la ejecuta sin entrar.
      
        
      ↳
      Step Into
      Entra dentro de la función que llama la línea para verla por dentro.
      
        
      ↰
      Step Out
      Termina la función actual y vuelve a quien la llamó.
      
        
      👁
      Variables y Watch
      Muestran el valor de cada variable ahora. Un watch vigila una expresión.

      1. Piensa: “¿qué valor esperaba en esta variable?”

      4. Avanza con Step Over / Step Into hasta ver cuándo cambia mal.
